# Развитие движка

## Архитектура

`Match` не зависит от DOM и Canvas. Внешний код подаёт структуру ввода в `tick(1/120, input)`, а визуализация читает состояние. Время кадра накапливается в `main.js`; темп меняет скорость накопления, не физический timestep. При паузе и потере фокуса клавиши очищаются. Быстрые нажатия сохраняются до ближайшего тика.

Состояния: `serve → toss → receive → set → attack`. Атака/скидка снова переводят игру в `receive`; переход через центр меняет владение. Завершение: `point`, `set-end`, `finished`. Счёт вынесен в `rules.js`, поэтому правила можно менять без привязки к рендеру.

Контакт изменяет скорость; между контактами движение мяча интегрируется. Столкновение с сеткой проверяет пересечение плоскости на протяжении шага, чтобы быстрый мяч не пролетал насквозь. Полёт под гравитацией точен для свободного падения без сопротивления; сопротивление интегрируется приближённо. Это не универсальный физический движок столкновений твёрдых тел.

## Новый удар

1. Добавьте запись в `ATTACKS` в `src/moves.js`, например:

```js
cross: {
  name: 'Новая комбинация',
  role: 'open',        // receiver | setter | quick | open
  x: 3.2,             // расстояние точки атаки от сетки
  flight: 1.1,        // секунды полёта паса
  height: 3.3,        // высота мяча у атакующего
  power: 1.05,
  hint: 'Описание ввода'
}
```

2. В `receptionChoice` / `setChoice` добавьте выбор записи по комбинации. Для выбора на самом ударе используется `tryAttack` в `engine.js`. Логику новой стадии лучше вынести в отдельную функцию, если она сложнее выбора параметров.
3. Если движение обычное, задайте цель/время контакта через `launchTo`. После запуска не меняйте позиции мяча вручную. Для специального аркадного поведения создайте явный эффект, как у `ball.special === 'thunder'`; такой эффект должен быть выключаемым независимо от общей физики.
4. Добавьте название/последовательность в справку `moveRows` и подсказку текущей стадии, если она нужна.
5. Добавьте тест реального розыгрыша с новой комбинацией: должно происходить нужное касание и меняться траектория. Одного теста записи в таблице недостаточно.

Сейчас каталог статический и редактируется в исходниках. Это сознательно простая начальная архитектура, а не готовая система модов или визуальный редактор комбинаций. Следующее масштабирование: декларативные переходы комбинаций с условиями ввода, временем буферизации и анимационными событиями.

## Расширения с наибольшим эффектом

- Контрольные трассы оригинала и профиль таймингов по измерениям.
- Командные и индивидуальные характеристики с подтверждённой моделью влияния.
- Редактор полного состава, замены и правила ротации отдельно от четырёх отображаемых ролей.
- Запись входных событий и seed для повторов, пошаговый просмотр и сравнение версий физики.
- Вторая локальная команда ввода; протокол движка уже отделён от DOM, но два игрока пока не реализованы.

## Настройки

`DEFAULTS` и `LIMITS` определяют базовый профиль и проверку JSON. Не добавляйте параметры только в интерфейс: расширьте проверку импорта, значения по умолчанию и документацию. Изменения лаборатории применяются прямо в текущем розыгрыше; для честного сравнения сбрасывайте матч после смены профиля.

`npm.cmd test` запускает тесты без сторонних зависимостей. Основной контракт — конечные координаты, корректная смена состояний и правил, отсутствие зависших матчей. Сходство с оригиналом требует отдельной проверки на трассах, тесты движка его не гарантируют.
