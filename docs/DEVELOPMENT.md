# Развитие версии 02

## Слои

| Файл | Ответственность |
|---|---|
| `src/engine.js` | `Match`, стадии розыгрыша, ручные разрешения контактов, игроки и CPU |
| `src/moves.js` | `SHOTS`, `SERVES`, заряд, углы и ограниченная помощь пасу |
| `src/input.js` | Физические коды клавиш и буфер коротких нажатий |
| `src/physics.js` | Баллистика, сопротивление, вращение, сетка и прогноз |
| `src/rules.js` | Очки и сеты |
| `src/renderer.js` | Пиксельные персонажи, 2D-анимации и площадка |
| `src/main.js` | DOM, часы, пауза, настройки, сохранение |
| `src/guide.js` | Общий текст встроенной и печатной методички |

`Match` работает без DOM. `tick(1/120, input)` изменяет состояние, renderer его читает. Темп меняет накопление времени в `main.js`, не шаг симуляции. Единицы: метры, секунды, метры/секунду. Игра плоская: координата глубины мяча постоянна.

## Стадии и фазы

Стадии матча: `serve → serve-motion → rally → point/set-end → serve`, затем `finished`. Отдельное поле `teamPhases[team]` описывает атаку/защиту и доступность K. На своей стороне после паса включается атака; после возврата сопернику — защита.

Ввод: `{axis, up, down, low, loft, drive, block, jump, dive, switch}`. Клавиши движения и модификаторов во время заряда не перемещают игрока. Каждый удар привязан к `playerId`: нельзя зарядить одним и мгновенно передать попытку другому.

`charge` начинается новым нажатием J/L/I, накапливает силу и читает текущие модификаторы. При отпускании создаётся `pending` с окном 0.32 игровых секунды. Только оно разрешает обычный контакт человеческой команды, затем расходуется или истекает. Внутри движка удержание само не бьёт. При паузе, открытии диалога и потере фокуса ввод и незавершённая попытка очищаются.

Подача после отпускания проходит короткую стадию `serve-motion` и один контакт. На ней Q заблокирована. После подачи человек не бежит автоматически. `autoSelect` выбирает только маркер следующего игрока.

## Удары и помощь

`SHOTS.low/loft/drive` задают диапазон скорости, угол, высоту контакта, радиус досягаемости и позу. `SERVES` — отдельные параметры трёх подач. `shotImpulse` сначала вычисляет свободный импульс по силе/направлению; W/S меняют угол, воздушная I получает более плоскую траекторию.

Для J/L помощь ищет партнёра в выбранном направлении, если прогнозируемый мяч уже проходит в пределах 1.65 м. Решатель `launchTo` предлагает небольшую коррекцию, ограниченную по каждой компоненте 14% исходной скорости. Помощь не перемещает игроков и не направляет мяч после запуска. Подача и I не имеют автоприцела.

Чтобы расширить существующий удар, меняйте его параметры или добавьте условие в `shotImpulse`. Для новой кнопки/типа нужны: запись в каталоге, поле `EMPTY_INPUT`, mapping в `InputBuffer`, правила `canContact` и имя/поза/методичка. Для комбинации из нескольких касаний сохраняйте её контекст отдельно, не обходя `pending` автоматическим ударом человеческой команды.

## Прыжок, нырок, блок

Обычный прыжок запрещает горизонтальное движение до приземления. Нырок — отдельное состояние `diving` с фиксированным `diveVelocity`, затем `recovery`: лежание и подъём. Во время нырка доступен только ручной J у низкого мяча.

`requestBlock` выбирает одного свободного стоящего игрока у сетки. Повторный вызов допускается только по новому нажатию K в защите. Руки блокирующего могут встретить мяч после нажатия без J. CPU планирует максимум одну попытку на удар с вероятностью по сложности.

Контакт соперника, включая блок на прежней стороне сетки, меняет `lastTouch`, очищает `lastPlayer` и сбрасывает счётчики. Не привязывайте новое владение к пересечению центра: это возвращает ошибку «не могу принять после блока».

## Физика и проверка

Между контактами мяч интегрируется под гравитацией с квадратичным сопротивлением и простым эффектом вращения. Сетка проверяется по пересечению плоскости между двумя положениями. Контакт рук задаёт новый импульс, а не телепортирует мяч в точку назначения. Это специальная модель игры, не универсальный движок твёрдых тел.

`npm.cmd test` покрывает основные контракты и регрессии. Длинный матч CPU использует короткие сеты и начисление за каждый розыгрыш; отдельные тесты проверяют sideout, потолок и пятый сет. Матчи CPU на sideout могут быть долгими — несколько переходов подачи подряд не дают очков.

Настройки расширяйте одновременно в `DEFAULTS`, `LIMITS`, `sanitizeConfig`, интерфейсе и документации. Схема JSON версии 2 отделена от первой. После изменения физики заново проверьте диапазоны рабочей силы подачи и паса.
