# Разработка текущей игры

Текущая игра находится в корне: `index.html`, `src/`, `tests/`, `style.css`, `dynamic.css`, `settings.css`. `npm start` обслуживает ее на `127.0.0.1:4173`. `PLAY.cmd` и `PLAY-DYNAMIC.cmd` используют общий `launch.mjs`, который сначала проверяет готовность сервера и затем открывает браузер. `PORT` меняет порт запуска.

## Границы модулей

| Модуль                                               | Ответственность                                                           |
| ---------------------------------------------------- | ------------------------------------------------------------------------- |
| `engine.js`                                          | Стадии матча, порядок шага симуляции, движение и решения CPU              |
| `controllers.js`                                     | Состояние и принадлежность контроллеров; формирование направления         |
| `contacts.js`, `contact-rules.js`                    | Разрешение контактов и объяснение отказов                                 |
| `serve-flow.js`                                      | Выбор подачи CPU, подброс, исполнение подачи                              |
| `drills.js`, `challenges.js`, `tutorial.js`          | Упражнения, испытания и обучение через один Match                         |
| `manual-impulse.js`                                  | Физика ручного удара                                                      |
| `profile-impulse.js`                                 | Профильные удары CPU, подача и старые контракты                           |
| `physics.js`                                         | Общий интегратор, сетка, прогноз и решение траектории                     |
| `settings-schema.js`                                 | Метаданные настроек, их область применения, единицы и диапазоны           |
| `config.js`, `shot-settings.js`, `serve-settings.js` | Дефолты, ограничения и профили                                            |
| `settings-file.js`                                   | Формат сохранения версии 5; миграция версий 2–4 и старых сырых объектов   |
| `records.js`                                         | Отдельные рекорды для физических профилей                                 |
| `finish-screen.js`                                   | Единственный владелец DOM итогового экрана                                |
| `replay.js`                                          | Полный снимок для повторной попытки и отдельные кадры сцены для просмотра |
| `main.js`                                            | Связь браузера, часов, ввода, модальных окон и игры                       |

Симуляция работает без DOM. Единицы — метры и секунды, шаг — 1/120 с. `gameSpeed` управляет накоплением времени в браузере. Косметическая случайность отделена от игрового RNG.

Каждый контроллер имеет явные `slot`, `team`, `charge`, `pending`, `previousInput` и другие поля. Методы обработки принимают это состояние аргументом. P2 в кооперативе не подменяет `selected[0]` или `inputs[0]`. Методы Match оставлены как небольшой публичный фасад для упражнений и регрессий.

Ручной и профильный импульсы разделены на разные модули. Внутренний профиль `dynamic: false` пока поддерживается для исторических контрактов. Его проверки находятся в `tests/compatibility/` и не подменяют проверки текущего поведения в `tests/`.

## Стандарт и сохранения

`config/standard.json` — полный профиль, предоставленный пользователем 18 октября 2026. Тест сравнивает его с DEFAULTS целиком. Изменение стандарта требует согласованного обновления этого файла, DEFAULTS и проверок достижимости испытаний.

Сохраненные настройки пользователя имеют приоритет над стандартом. Сброс возвращает DEFAULTS. Значения, похожие на старый дефолт, больше не переписываются по числовому совпадению. Правый стик мигрирует в отключенное состояние; он не имеет фиктивного селектора в интерфейсе.

Прогресс кубка и прежние рекорды сохраняются. Новые рекорды разделены по физическим профилям; внешний вид и музыка не создают новую категорию. Если во время десятимячевой попытки менялась физика, рекорд не обновляется. Это не запрещает экспериментировать с настройками.

## Проверки

- `npm test` — текущий профиль, кооператив, клуб, реальные контакты, музыка и сцена.
- `npm run test:compatibility` — явно выделенные прежние контракты на текущих общих модулях.
- `npm run test:legacy` — исходные тесты неизменяемого frozen v2.
- `npm run test:classic` — Classic.
- `npm run verify:archives` — 116 SHA-256 архивного frozen-каталога; текущий корень не сравнивается с архивом.
- `npm run check` — форматирование, текущие и совместимые контракты, Classic и контрольные суммы.
- `npm run test:browser` — реальные Chromium, DOM, сохранение, лаборатории, обучение, результаты и Gamepad API с двумя виртуальными устройствами.
- `npm run check:all` — все обязательные проверки, включая браузер.

Для браузерных проверок после `npm ci` требуется `npx playwright install chromium`; в Linux CI используется `--with-deps`. Физические геймпады полезно дополнительно проверять вручную: виртуальные устройства проверяют код опроса, но не драйверы.

Тест лаборатории сравнивает ее импульс с исполнением через разрешение настоящего ручного контакта, при разных сторонах, силе, направлении и модификаторах. Тесты испытаний исполняют реальные игровые шаги; сценарии для предоставленного стандарта сохранены в `tests/fixtures/standard-challenges.json`.

## Диагностика и производительность

Открыть `/?debug=1` для причин отказа контакта. Диагностика вызывает те же правила, что и матч. Признак доступной геометрии не отменяет требований к подготовленным ладоням и времени нажатия.

`npm run benchmark` измеряет в headless Chromium время двух шагов симуляции и отрисовки сцены. После прогрева собираются 1680 отсчетов на режим; результат записывается в игнорируемый `.cache/benchmark.json`. Это время работы на синтетический кадр 60 Гц, не обещание реальных FPS или задержки геймпада. Условия демо и кооператива различаются; сравнивать их как одинаковую нагрузку нельзя.

Прогноз принимающего разделяется между двумя владельцами только для одинакового состояния мяча и настроек. Профили контакта вычисляются один раз на прогноз, а не на каждого игрока и отсчет. Replay сохраняет полное состояние один раз в начале розыгрыша; кадры просмотра содержат состояние сцены и разделяют неизменяемую копию настроек. DOM тактической панели обновляется с интервалом около 65 мс. Текущая траектория рисуется один раз, а не по разу на каждый пустой слот контроллера.

## Архивы

`versions/frozen-v2-2026-10-12/` неизменяем, включая его вложенные файлы. `versions/classic-v1/` — самостоятельный Classic. Форматтер исключает оба архива и манифест. Исторические заметки находятся в `docs/history/`; их описания механики не являются инструкциями для текущей игры.

Старый адрес `/versions/dynamic-v3/...` перенаправляется на актуальные файлы в корне с сохранением query string. Вложенная копия Classic и одноразовые скрипты правки исходников из Dynamic удалены из рабочей поставки. Нужные исходники до преобразования сохранены локально в игнорируемом `.cache/before-audit-refactor/`.

## Структура настроек после очистки

`settings-panels.js` задаёт общий каркас и навигацию, `contact-settings-ui.js` — единственный редактор игровых профилей ударов и подач. `settings-scope.js` разделяет косметику и симуляцию для интерфейса, планов CPU и рекордов. Закрытые редакторы создаются лениво. Косметическая длина рук не меняет физические ладони. Согласованные изменения и проверки описаны в [CLEANUP-2026-10-19.md](CLEANUP-2026-10-19.md).
